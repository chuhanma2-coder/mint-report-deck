# Mint Report Deck V0.4.1

把粗略中文笔记编译为来源可追溯、最少页数的 Mint 管理层材料：互动 HTML 由内置渲染器生成；可编辑 PPTX 由 Codex `Presentations` Skill 使用内置组件母版生成。

## 安装

把本仓库链接发给支持 Skills 的 Agent，并说：

```text
帮我安装这个 Skill：https://github.com/chuhanma2-coder/mint-report-deck
```

Codex 也可以按其 Skill 安装流程从 GitHub 仓库安装。安装后重新打开任务或刷新 Skills 列表。

## 使用

```text
使用 Mint 汇报 Skill，把下面的粗略笔记生成可编辑 PPTX 和互动 HTML。
如果一页能讲清，就只做一页。只使用我提供的事实。

【材料主题】
……

【给谁看 / 希望推动什么】
……

【已知事实】
……

【下一步】
……
```

复杂监管、法律、资本、信贷、定价或客户政策材料会先列出待确认项。当前 Agent 没有 `Presentations` 时，只生成内容结构和 HTML，并明确提示 PPTX 未生成。

## 设计原则

- 先冻结事实和实体名称，再判断逻辑关系。
- 默认从一页开始，不机械拆页。
- 用户说“必须一页、强制一页、不要拆页、只做一页”时，页数成为硬合同：先将背景、证据、关系、风险和行动编排进同一个页面命题；放不下则阻断并报告，不得擅自生成第二页。
- 前台—中台—后台、能力交接和价值传递优先使用能力链路；只有需要核对严格层级归属时才使用分层架构。
- 资金、监管闸门、重大风险和管理层决策必须从正文中单独提取，使用醒目的资金、风险或决策模块。
- 整份汇报先生成章节计划；所有一级章节的引言页共享同一套几何、字号和阅读顺序，避免三大块内容各自长成不同风格。
- 组件库不是固定页面清单。没有完全匹配的页面时，在受控页面家族内组合模块；容量不足则拆页，仍不匹配则标记版式复核，不用错误表格兜底。
- 无完整数值、单位、期间、统计对象和来源时不生成图表。
- 数字必须识别为输入、结果、目标、阈值、差额、构成、趋势或情景；公式、阈值和差额优先使用结构图，不退化成普通双栏文字。
- 主要信息覆盖、数字计算、视觉显著性任一失败时最多自动修复两轮；仍失败则阻断正式交付。
- PPTX 与 HTML 共用 `content-map.json` 和 `deck-spec.json`。
